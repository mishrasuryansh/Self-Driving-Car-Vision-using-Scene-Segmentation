+PROJECT CONTEXT
+Addresses Section 15.3's identified deployment risk ("Storage costs/limits for uploaded media... staging environment fills up or exceeds free-tier quota") with its documented mitigation ("Auto-expire job artifacts after N days").
+TASK OBJECTIVE
+A scheduled worker task that removes job artifacts (and updates/deletes their records per a defined retention policy) older than a configurable N days.
+INPUT CONTEXT
+Current files: storage.py (T039), job.py (T033). Reference: Section 15.3 mitigation.
+FILES TO CREATE
+/worker/app/tasks/cleanup_task.py
+FILES TO MODIFY
+None.
+IMPLEMENTATION REQUIREMENTS
+A task querying job records with createdAt older than a configurable retention threshold (read from config, defaulting to a documented value, e.g. 30 days); for each matched record, deletes the associated stored artifacts via T039's delete() and removes or marks the job record per a clearly documented retention policy (choose delete-the-row vs. mark-as-expired-but-keep-metadata, and state the choice explicitly in Implementation Notes); dry-run/logging-only mode supported so this can be verified safely before being scheduled for real execution; idempotent — safe to run repeatedly without error on already-cleaned records.
+ENGINEERING STANDARDS
+No irreversible destructive operation without a preceding dry-run verification path. No hardcoded retention period — configurable.
+CONSTRAINTS
+Do not wire this task into an actual cron/periodic scheduler in this task — scheduling infrastructure belongs to the deployment epic (Epic 8); this task only implements the cleanup logic itself, invocable manually or by a scheduler added later. Do not modify storage.py or job.py.
+
+ACCEPTANCE CRITERIA
+
+ Running the cleanup task against seeded old records removes their files and rows/markers per the documented policy.
+EXIT CRITERIA
+✓ Dry-run mode verified against seeded data with no destructive action taken ✓ Live-run mode verified against seeded data, confirming correct records affected ✓ No lint errors ✓ Retention policy documented ✓ Commit ready
+TESTING REQUIREMENTS
+Integration test: seed job records with a mix of old and recent createdAt timestamps and associated stored files; run in dry-run mode and confirm no files/records are altered but the correct candidates are logged; run in live mode and confirm only the old records' files/rows are removed, recent ones untouched. Re-run to confirm idempotency.
